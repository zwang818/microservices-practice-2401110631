# 第 04 周作业

## 业务建模

本周围绕“设备租赁与预约管理平台”的设备查询与时间段预约场景完成业务建模，并在单体 Spring Boot 工程中实现可运行的内存版本。

### 核心实体及关系

- `Equipment`（设备）：记录设备编号、名称、分类、日租金、押金、设备状态、说明和创建时间。
- `Reservation`（预约）：记录预约设备、租用人、开始时间、结束时间、预约状态和创建时间。
- 一个设备可以对应多个预约，因此 `Equipment` 与 `Reservation` 是一对多关系；每条预约只属于一个设备。

### 核心业务流程

1. 管理员创建可租赁设备，系统校验设备编号不能重复。
2. 用户通过设备接口查询设备列表或设备详情。
3. 用户选择设备和时间段后提交预约。
4. 预约服务校验设备是否存在、设备是否可用、结束时间是否晚于开始时间，以及所选时间段是否与已有有效预约冲突。
5. 校验通过后生成状态为 `CONFIRMED` 的预约，并可通过预约接口查询结果。

### 业务规则

只有状态为 `CONFIRMED` 的预约参与时间冲突判断。当已有预约满足“已有开始时间早于新预约结束时间，并且已有结束时间晚于新预约开始时间”时，判定两个时间段重叠，拒绝创建新预约并返回 HTTP 409。前一个预约的结束时间等于后一个预约的开始时间时不算冲突。

### 本次实现

- 模型：`Equipment`、`Reservation` 及其状态枚举。
- 服务：`EquipmentService`、`ReservationService`，业务规则集中在 Service 层。
- 接口：设备和预约分别提供创建、列表查询、详情查询，共 6 个 REST 接口，统一使用 `/api` 前缀。
- 请求与响应：使用独立 DTO，并对必填字段、金额和设备 ID 进行参数校验。
- 异常处理：参数错误返回 400、资源不存在返回 404、设备编号重复或预约冲突返回 409。
- 当前数据暂存在内存中，数据库持久化将在后续任务中接入。

### 测试说明

执行命令：

```bash
cd monolith
./mvnw test
```

自动化测试覆盖正常创建预约、拒绝重叠预约、允许首尾相接的预约，以及拒绝无效时间范围。

实际执行结果为 `BUILD SUCCESS`，共运行 5 个测试，失败 0、错误 0、跳过 0。启动应用后，创建设备和创建预约均返回 HTTP 201，设备与预约列表查询返回 HTTP 200，健康检查返回 `UP`；再次提交时间重叠的预约返回 HTTP 409 和“该设备在所选时间段已被预约”，说明核心业务规则已经生效。
