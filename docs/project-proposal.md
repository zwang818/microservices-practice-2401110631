# 项目提案：设备租赁与预约管理平台

## 项目名称

**设备租赁与预约管理平台**

## 项目概述

本项目面向需要短期使用摄影器材、实验设备或运动器材的用户，提供设备查询、时间段预约、库存锁定、租赁订单、领取归还、费用结算、维修管理和消息通知等功能。平台以设备生命周期为主线，统一记录设备从可租、预约、领取、使用、归还、维修到再次可租的状态变化，减少人工登记造成的预约冲突和状态错误。

## 目标用户

| 用户角色 | 主要需求 |
| --- | --- |
| 租赁用户 | 查询设备及可用时间，提交或取消预约，查看订单、费用和到期提醒 |
| 设备管理员 | 维护设备与库存，处理预约，办理领取和归还，登记验收结果 |
| 维修人员 | 接收维修任务，记录检测结果与维修进度，确认设备能否重新出租 |
| 平台管理员 | 管理用户、角色、设备分类和业务规则，查看异常订单与运营数据 |

## 优先实现的业务场景

### 查询并预约可用设备

首个业务场景聚焦于用户在指定时间段内查询并预约设备，其基本流程如下：

1. 用户选择设备类型、预计租赁开始时间和结束时间。
2. 系统查询符合条件且状态为“可租”的设备。
3. 用户选择一台设备并提交预约申请。
4. 系统检查该设备在目标时间段内是否存在冲突预约。
5. 校验通过后，系统创建预约记录并锁定对应时间段的设备库存。
6. 系统向用户返回预约结果；若发生冲突，则提示用户重新选择设备或时间。

选择该场景作为首个业务场景，是因为它连接了设备信息、可用状态、时间冲突校验和预约记录，是后续扩展租赁订单、领取归还、费用结算与消息通知的基础。

> 第 03 周只创建可运行的 Spring Boot 基础工程，不实现上述业务逻辑。本节仅用于明确后续开发方向。

## 两个核心模型

### 1. 设备（Equipment）

设备模型描述平台中可被查询、预约和租赁的具体设备，是库存与状态管理的基础。

计划包含的核心信息：

- 设备唯一标识
- 设备名称与分类
- 规格或型号
- 租赁单价与押金
- 当前状态，如可租、已锁定、租赁中、维修中或已下架
- 设备说明和图片信息

设备状态将决定其是否能够参与查询和预约。后续领取、归还和维修流程也会驱动设备状态变化。

### 2. 预约（Reservation）

预约模型记录用户在指定时间段内对某台设备提出的租赁请求，用于处理预约冲突和库存锁定。

计划包含的核心信息：

- 预约唯一标识
- 用户标识
- 设备标识
- 租赁开始时间与结束时间
- 预约状态，如待确认、已确认、已取消、已过期或已完成
- 创建时间与更新时间

系统创建预约前，需要根据设备标识和租赁时间段进行冲突校验。预约取消或超时后，应释放已锁定的设备资源。

## 当前范围

第 03 周只完成 Spring Boot 工程起步，包括应用启动、基础 YAML 配置、简单 GET 接口、Actuator 健康检查和 Spring 上下文启动测试。本周不实现设备与预约模型，不实现业务 CRUD、Service、Repository 或数据库持久化。
